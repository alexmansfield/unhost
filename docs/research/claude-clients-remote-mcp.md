# How Claude clients consume a remote MCP server

Research ticket: [#6](https://github.com/alexmansfield/unhost/issues/6) (part of map [#1](https://github.com/alexmansfield/unhost/issues/1)).
Investigated 2026-09-21 against primary sources: Anthropic's connector docs (`claude.com/docs/connectors`), the Claude Code docs and changelog, the MCP specification (2025-06-18, 2025-11-25, 2026-07-28), and `laravel/mcp` v0.9.5 as vendored in `scatterblend.localhost`.

**Status legend.** Every claim is tagged:

- **Documented** — stated in Anthropic's or the MCP project's official docs, or in source code.
- **Observed** — reported with wire evidence on Anthropic's own tracker (`anthropics/claude-ai-mcp`, where Anthropic staff triage) or seen in this session. Not a promise; may change.
- **Unknown** — no primary source found. The nearest source is named.

Client shorthand: **claude.ai** = the hosted surfaces (web, Desktop, mobile) that share one connector runtime; **Cowork** = the agentic mode of Claude Desktop; **Claude Code** = the CLI with `claude mcp add --transport http`.

## Answers

1. **OAuth expectations.** All three clients discover the authorization server via RFC 9728 (`WWW-Authenticate: Bearer resource_metadata=…` on a `401`, falling back to `/.well-known/oauth-protected-resource[/path]`), then RFC 8414 or OIDC discovery, and always send PKCE `S256` and the RFC 8707 `resource` parameter. Registration order is pre-registered client → CIMD (only if the AS advertises `client_id_metadata_document_supported: true` **and** `"none"` in `token_endpoint_auth_methods_supported`) → DCR. Redirect URI is `https://claude.ai/api/mcp/auth_callback` for claude.ai/Cowork and a port-varying loopback `http://localhost:PORT/callback` (or `127.0.0.1`) for Claude Code. Refresh is reactive on `401` (claude.ai also refreshes ~5 min before expiry; Claude Code retries once). Deviations from spec: claude.ai only honours `WWW-Authenticate` on a `401` (not `200`), uses only the *first* `authorization_servers` entry, unions step-up scopes with discovery scopes, and the spec's "MUST rotate refresh tokens for public clients" lands on the server. `laravel/mcp`'s `oauthRoutes()` serves RFC 8414 + RFC 9728 + DCR (public client, S256) but not CIMD, so Claude will pick **DCR** and register a new Passport client per fresh connection. (Documented.)

2. **Tool list behaviour.** claude.ai fetches `tools/list` on connect and caches the catalogue **above the MCP session** (Anthropic staff: "we cache the list for 1h"); reconnect, remove/re-add and even `list_changed` do not reliably bust it, only a URL string it has not seen before does (Observed). Claude Code fetches at startup (or from an optional discovery cache), honours `list_changed` (Documented), and defers all MCP tool schemas behind `ToolSearch` by default — only names and server instructions are loaded, descriptions/instructions truncated at 2 KB (Documented). There is no documented tool-count cap; the API-level guidance is that selection accuracy degrades past 30–50 tools and to defer once definitions exceed ~10 k tokens (Documented). `listChanged: false` from `laravel/mcp` costs nothing on claude.ai (it ignores the notification anyway) and only forgoes live refresh on Claude Code.

3. **Elicitation.** Claude Code supports form **and** URL mode since v2.1.76 (Documented). claude.ai declares **no** `elicitation` capability (Observed, 2026-08; open enhancement #153). Cowork declares `elicitation: {}` (form only) on protocol 2026-07-28 but does not service it — the call hangs 180 s (Observed, #1046, open). A URL in a `200 isError:true` result is **passed to the model as text and the turn moves on** on claude.ai (Documented) — relay to the user is by the model, not the client, so it is not guaranteed verbatim. The **documented** client-driven browser round-trip is a `403` with `WWW-Authenticate: Bearer error="insufficient_scope", scope="…"` (step-up): claude.ai re-runs consent and retries the same call; Claude Code fails the call with a "needs additional permissions" message naming the scope and flags the server for re-auth in `/mcp`.

4. **Result limits.** Claude Code: warning at 10 000 tokens, default cap 25 000 tokens (`MAX_MCP_OUTPUT_TOKENS`); over the cap the result is written to a file under `~/.claude/projects/<session>/tool-results/` and replaced with the path; a tool can raise its own cap with `_meta["anthropic/maxResultSizeChars"]` up to 500 000 chars (Documented). claude.ai and Cowork: **Unknown** — no documented limit; review guidance is "keep responses reasonably sized"; an "Output abbreviated due to length limit" marker has been observed on host-side tool-search payloads (#949).

5. **Fetch the schema, then call.** Precedent exists in three places: the API's Tool Search Tool (`defer_loading`; Claude "searches the catalog, discovers `get_weather`, and calls it"), Claude Code's `ToolSearch` (all MCP tools deferred by default), and `laravel/mcp`'s `search_tools` / `execute_tools` pair. In the first two the deferred tool is **not callable until loaded**, which is what makes the search step reliable; a gateway `call-site-tool` that is always callable does not get that guarantee, so reliability must come from (a) the `call-site-tool` description saying to call `list-site-tools` first and (b) server-side schema validation returning an actionable error that includes the schema. Server `instructions` are not a safe carrier: claude.ai does not pass them to the model (Observed, #93) and they go stale in Cowork (Observed, #811).

6. **Quirks.** `site` as slug vs URL: no client-specific documentation; Anthropic's guidance is that models handle natural-language identifiers better than opaque IDs and parameter names should be unambiguous (`site_slug`, not `site`). Two connectors with identical tool names do not collide in Claude Code — tools are namespaced `mcp__<server>__<tool>` and claude.ai connectors arrive as `claude.ai <name>` servers (Documented + Observed in this session with two RestlessWP connectors). claude.ai's per-connector tool toggles and org-level `ask`/`blocked` controls work per connector, so a shared tool name is not a problem there either.

## 1. Which spec each party speaks

- The MCP spec has five revisions; the current one is **2026-07-28**, which removes `initialize`/sessions, adds `server/discover`, replaces server-initiated `elicitation/create` with Multi Round-Trip Requests (`InputRequiredResult`), requires `ttlMs`/`cacheScope` on `tools/list`, says servers **SHOULD** return tools in deterministic order for client caching, and **deprecates DCR in favour of CIMD**. Source: [2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog).
- claude.ai custom connectors negotiated `2025-11-25` as of 2026-08-12 ([#153, comment by abregeon](https://github.com/anthropics/claude-ai-mcp/issues/153)); by 2026-09-17 claude.ai's enumerator sends `server/discover` with `MCP-Protocol-Version: 2026-07-28` and `Mcp-Method` headers *when the server answers the probe* ([#1044](https://github.com/anthropics/claude-ai-mcp/issues/1044)). Anthropic's connector docs still cite the 2025-11-25 authorization sections ([authentication](https://claude.com/docs/connectors/building/authentication)).
- Claude Code's v2 runtime "adds MCP protocol revision 2026-07-28", "asks HTTP servers whether they support the newer revision, and uses it with those that do … It connects to every other server as v1 does" ([MCP client runtimes](https://code.claude.com/docs/en/mcp#mcp-client-runtimes)).
- Cowork identifies as `claude-code/2.1.273 (remote_cowork)` and negotiates 2026-07-28 ([#1046](https://github.com/anthropics/claude-ai-mcp/issues/1046)). Anthropic says Cowork "uses the same agentic architecture that powers Claude Code" ([Cowork overview](https://claude.com/docs/cowork/overview)).
- `laravel/mcp` v0.9.5 supports `2024-11-05` … `2025-11-25` (`src/Enums/ProtocolVersion.php`) and answers unknown methods such as `server/discover` with JSON-RPC `-32601` (`src/Server.php:205`). Both Anthropic clients fall back to the `initialize` handshake, so this is compatible today; the 2026-07-28 cache hints (`ttlMs`) and deterministic ordering are not available to the gateway until laravel/mcp adds them.

## 2. OAuth

### 2.1 What the spec requires

Spec 2025-11-25 (the revision Anthropic's docs cite; 2026-07-28 keeps these rules): MCP servers **MUST** implement RFC 9728 and advertise the AS via `WWW-Authenticate … resource_metadata=` on `401` and/or the well-known URI (path-suffixed first, then root); clients **MUST** support both. Authorization servers **MUST** provide RFC 8414 or OIDC discovery; clients try `/.well-known/oauth-authorization-server[/path]` before `/.well-known/openid-configuration`. Client registration priority: pre-registered → CIMD (`client_id_metadata_document_supported: true`) → DCR (`registration_endpoint`) → prompt the user. Clients **MUST** implement PKCE with `S256`, **MUST** refuse to proceed if `code_challenge_methods_supported` is absent from AS metadata, **MUST** send RFC 8707 `resource` on authorization and token requests, **MUST NOT** put tokens in the query string, and **MUST** have redirect URIs registered; ASes **MUST** validate exact redirect URIs and **MUST** rotate refresh tokens for public clients. Source: [2025-11-25 authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization).

### 2.2 claude.ai / Cowork (hosted surfaces)

Anthropic's page opens with "Claude's auth support differs in a few places from the generic MCP specification" and states that "the same infrastructure backs Claude.ai, Claude Desktop, Claude mobile, Claude Code, and Cowork" ([authentication](https://claude.com/docs/connectors/building/authentication)). Documented specifics:

- **Discovery.** "The `401` status is required — Claude does not honor a `WWW-Authenticate` header on a `200` response". Without a `resource_metadata` pointer Claude probes `/.well-known/oauth-protected-resource/<your-mcp-path>` then `/.well-known/oauth-protected-resource`. "If you list more than one [authorization server], Claude uses the first entry and does not fall back". AS metadata via RFC 8414 or OIDC; "Claude tries `/.well-known/oauth-authorization-server` first, then falls back to `/.well-known/openid-configuration`" ([troubleshooting](https://claude.com/docs/connectors/building/troubleshooting)). Discovery documents are cached "globally, keyed by URL, with a staleness window of about five minutes" ([lazy authentication](https://claude.com/docs/connectors/building/lazy-authentication#oauth-discovery-caching)).
- **Registration.** Custom-connector dialog offers "Use Claude's published identity" (CIMD, recommended), "Register automatically" (DCR — "adds client registrations over time"), or "Use your own OAuth client" ([remote-mcp](https://claude.com/docs/connectors/custom/remote-mcp#the-add-custom-connector-dialog-field-by-field)). "Claude selects CIMD only when your authorization server metadata advertises **both** `"client_id_metadata_document_supported": true` **and** `"none"` in `token_endpoint_auth_methods_supported` … If either is missing, Claude falls back to DCR." "DCR causes Claude to register a new client on every fresh connection, which can result in very large numbers of registered clients on your authorization server." A user-entered client secret is optional; blank ⇒ public client.
- **PKCE.** "Claude includes a PKCE `code_challenge` with `code_challenge_method=S256` on every authorization request, regardless of which registration mechanism it uses."
- **Redirect URI.** "For the hosted Claude surfaces (Claude.ai web, Desktop, mobile, and Cowork), register … `https://claude.ai/api/mcp/auth_callback`".
- **`resource`.** "Claude sends the RFC 8707 `resource` parameter on authorization and token requests, set to the canonical form of your MCP server URL — lowercase scheme and host, no trailing slash, no fragment, no default port — including any path component" ([troubleshooting](https://claude.com/docs/connectors/building/troubleshooting#authorization-with-the-mcp-server-failed)).
- **Scopes.** `scope` from the `401` header, else PRM `scopes_supported`; `offline_access` appended when the AS lists it.
- **Refresh.** "Claude refreshes tokens reactively on a 401 response, with a proactive refresh up to five minutes before the stored expiry." Return `invalid_grant` for dead refresh tokens; rotate refresh tokens; `/token` must accept `application/x-www-form-urlencoded`, `/register` receives `application/json`. Endpoint latency: 10 s for discovery/registration/token, 30 s for refresh.
- **No client_credentials.** "A pure machine-to-machine `client_credentials` grant … is not supported. Every connection requires user consent."
- **Network.** Egress from `160.79.104.0/21`; connectors are IPv4-only; private/CGNAT/loopback DNS answers are rejected before any request; a `3xx` to another host drops the `Authorization` header ([troubleshooting](https://claude.com/docs/connectors/building/troubleshooting#couldnt-reach-the-mcp-server)).
- **Immutable auth settings.** "Authentication settings (OAuth credentials and request headers) can't be changed after a connector is added. To change them, remove the connector and add it again" ([remote-mcp](https://claude.com/docs/connectors/custom/remote-mcp#managing-connectors)).
- **Cowork.** Custom connectors are "available on Claude, Cowork, and Claude Desktop" ([support article](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp)); Cowork "loads the ones enabled for your claude.ai account, synced at session start" ([Cowork overview](https://claude.com/docs/cowork/overview)). Claude Code's docs add that in the desktop app's local sessions "the desktop app registers the connectors as in-process `type: "sdk"` servers" ([how connectors reach Claude Code](https://code.claude.com/docs/en/mcp#how-connectors-reach-claude-code)). A separately documented path — *managed* Claude Desktop on third-party deployments — signs in on a fixed loopback `http://127.0.0.1:53280/callback` and registers via DCR ([3P extensions](https://claude.com/docs/cowork/3p/extensions)); that is an enterprise MDM configuration, not the claude.ai connector path.

### 2.3 Claude Code

- `claude mcp add --transport http <name> <url>`; scopes `local` (default) / `project` (`.mcp.json`) / `user` ([installing](https://code.claude.com/docs/en/mcp#option-1-add-a-remote-http-server)).
- Discovery: "By default, Claude Code first checks RFC 9728 Protected Resource Metadata at `/.well-known/oauth-protected-resource`, then falls back to RFC 8414 authorization server metadata at `/.well-known/oauth-authorization-server`"; `oauth.authServerMetadataUrl` overrides ([override discovery](https://code.claude.com/docs/en/mcp#override-oauth-metadata-discovery)). "A custom server that returns a `WWW-Authenticate` header pointing to its authorization server gets the same automatic discovery as any other remote server."
- Registration: DCR by default; "Claude Code also supports servers that use a Client ID Metadata Document (CIMD) instead of Dynamic Client Registration, and discovers these automatically" (CIMD added in v2.1.81, [changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)). Its CIMD at `https://claude.ai/oauth/claude-code-client-metadata` declares `client_name: "Claude Code"`, `redirect_uris: ["http://localhost/callback", "http://127.0.0.1/callback"]`, `grant_types: ["authorization_code", "refresh_token"]`, `token_endpoint_auth_method: "none"` (fetched 2026-09-21). Pre-configured `--client-id` / `--client-secret` / `--callback-port` since v2.1.30.
- Redirect URI: "By default, Claude Code picks a random available port for the OAuth callback. Use `--callback-port` to fix the port so it matches a pre-registered redirect URI of the form `http://localhost:PORT/callback`" ([fixed callback port](https://code.claude.com/docs/en/mcp#use-a-fixed-oauth-callback-port)). Anthropic asks ASes to "accept both with the port component ignored" ([callback URLs](https://claude.com/docs/connectors/building/authentication#callback-urls)). v2.1.229 briefly sent `127.0.0.1` and broke exact-match servers.
- Scopes: as of v2.1.196 "Claude Code requests the scope provided by the server's `WWW-Authenticate` header or its protected resource metadata, and sends no `scope` parameter when neither provides one"; `oauth.scopes` pins; `offline_access` appended ([restrict scopes](https://code.claude.com/docs/en/mcp#restrict-oauth-scopes)).
- Refresh: "When a request to an OAuth server you already signed in to returns `401 Unauthorized`, Claude Code refreshes the stored token, reconnects, and retries the request once." Rejected refresh token ⇒ notice → `/mcp` → **Re-authenticate**. Tokens in the macOS keychain ([authenticate](https://code.claude.com/docs/en/mcp#authenticate-with-remote-mcp-servers)).
- v2 runtime "Fails an MCP OAuth sign-in whose authorization response names an unexpected issuer" (RFC 9207 `iss` check).
- Anthropic-hosted connectors reached from Claude Code via claude.ai do not run local OAuth; a gateway added directly with `claude mcp add` does.

### 2.4 `laravel/mcp` v0.9.5 `oauthRoutes()` against these expectations

Source: `vendor/laravel/mcp/src/Server/Registrar.php` (`oauthRoutes`, `authorizationServerMetadata`, `protectedResourceMetadata`), `src/Server/Http/Controllers/OAuthRegisterController.php`, `src/Server/Middleware/AddWwwAuthenticateHeader.php`, `config/mcp.php`.

| Expectation | laravel/mcp 0.9.5 | Verdict |
|---|---|---|

| `WWW-Authenticate` on `401` | `AddWwwAuthenticateHeader` adds `Bearer realm="mcp", resource_metadata="<nested PRM route for request path>"` when oauth routes are registered | Meets "return 401, not a tool error". No `scope=` parameter is emitted, so Claude requests PRM `scopes_supported` (`mcp:use`). |
| RFC 8414 AS metadata | Root and `/{path}`; `issuer`, Passport `authorize`/`token` routes, `registration_endpoint`, `response_types_supported: [code]`, `code_challenge_methods_supported: [S256]`, `scopes_supported: [mcp:use]`, `grant_types_supported: [authorization_code, refresh_token]` | Meets spec; PKCE advertised as Claude requires. **No** `token_endpoint_auth_methods_supported`, **no** `client_id_metadata_document_supported`, no OIDC discovery. Consequence: Claude cannot select CIMD and falls back to DCR. The routes are only registered if the app has not already defined the exact URI (`hasGetRoute`), so the app can override the document. |
| DCR | `POST {prefix}/register` validates `redirect_uris` against `config('mcp.redirect_domains')` (default `['*']`; loopback allowed only when `*` or a localhost entry is listed), creates a Passport authorization-code client with `confidential: false`, returns `token_endpoint_auth_method: "none"`, `response_types: [code]`, HTTP 201 | Matches what Claude sends (`https://claude.ai/api/mcp/auth_callback` for claude.ai; `http://localhost:PORT/callback` for Claude Code — the loopback needs `http://localhost` in `redirect_domains` if `*` is removed). One Passport client row per claude.ai connect and per Claude Code login (documented DCR churn). |
| Refresh-token rotation for public clients | Delegated to Passport | Passport's behaviour, not laravel/mcp's — verify in the `oauth` module ticket. |
| Custom URL schemes (`claude://`) | `config('mcp.custom_schemes')` | Not needed by any of the three clients. |

Client side (`src/Client/OAuth/*`, `Client::web()`): laravel/mcp's own MCP client does RFC 9728 challenge parsing, RFC 8414 + OIDC discovery (path-aware), DCR, and PKCE; it has **no** CIMD support either. Relevant only if the gateway proxies to RestlessWP over OAuth rather than app passwords.

## 3. Tool list behaviour

### 3.1 Spec

`tools/list` supports pagination; servers that declare `listChanged` **SHOULD** send `notifications/tools/list_changed`; the spec never requires clients to act on it ([2025-06-18 tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)). 2026-07-28 adds "Servers **SHOULD** return tools from `tools/list` in a deterministic order to enable client-side caching and improve LLM prompt cache hit rates" and required `ttlMs`/`cacheScope` on list results, "complement[ing] existing `listChanged` notifications" ([changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog)).

### 3.2 claude.ai

- **When fetched.** On Connect: `tools/list` from `Anthropic/Toolbox/1.0.0` then `Anthropic/ClaudeAI/1.0.0` (server log in [#1044](https://github.com/anthropics/claude-ai-mcp/issues/1044)). Documented: "Claude checks the URL and pre-fills the authentication settings it detects" when adding ([remote-mcp](https://claude.com/docs/connectors/custom/remote-mcp)); the "Test this connection" button in managed Desktop runs `initialize` + `tools/list`.
- **Caching.** Anthropic collaborator on [#45](https://github.com/anthropics/claude-ai-mcp/issues/45) (2026-02-10): "At the moment we cache the list for 1h … The tools will automatically refresh … we have an upcoming 'Clear cache' button". On closing [#137](https://github.com/anthropics/claude-ai-mcp/issues/137) (2026-05-06) staff recorded "the stale catalog survives disconnect/reconnect, org-level delete-and-re-add, and full OAuth re-consent, and can persist 24h+ … the connector settings UI can show the updated tool list while the model still sees the old one". [#1044](https://github.com/anthropics/claude-ai-mcp/issues/1044) (2026-09-16/17): the server received `tools/list` and returned 22 tools on every reconnect, the model kept 17; a "Refresh tools list" button exists and its toast says "Tools list refreshed" but was a no-op for hours; the record turned over overnight; "A URL string the connector has not seen before starts a fresh record at once." A Claude Code session using the same connector saw fresh `instructions` but the stale tool registry.
- **`listChanged`.** [#45](https://github.com/anthropics/claude-ai-mcp/issues/45): the client receives the notification, sends `tools/list`, and "seems to use a stale cached tools list" — "a known issue on our backlog". So `listChanged: false` costs nothing on claude.ai today.
- **Host-side tool search.** Observed but undocumented: claude.ai runs a host-side `tool_search` over connector tools and force-loads every MCP-Apps (`ui`) tool into each search payload, truncating at ~30 definitions with "Output abbreviated due to length limit" ([#949](https://github.com/anthropics/claude-ai-mcp/issues/949)). Implication: on claude.ai the gateway's tool schemas may be deferred by the host too, and interactive-UI `_meta` should be avoided on the gateway's tools.
- **Server `instructions`.** [#93](https://github.com/anthropics/claude-ai-mcp/issues/93) (open): "Claude.ai appears to silently ignore the `instructions` field".
- **Tool toggles.** Users can disable individual tools per connector and per conversation; Team/Enterprise owners can set a tool to `ask` or `blocked` ([support article](https://support.claude.com/en/articles/11175166-getting-started-with-custom-connectors-using-remote-mcp), [remote-mcp](https://claude.com/docs/connectors/custom/remote-mcp#tool-actions)).

### 3.3 Claude Code

- **When fetched.** At startup (servers "connect in the background by default"); with `MCP_DISCOVERY_CACHE=1` (off by default since v2.1.238 unless rolled out) a remote server shows `cached 2h ago · connects on first use · N tools` and connects on first call ([managing servers](https://code.claude.com/docs/en/mcp#managing-your-servers)). `/mcp` → Reconnect refetches.
- **`listChanged`.** "Claude Code supports MCP `list_changed` notifications … automatically refreshes the available capabilities" (since v2.1.0); "If a refresh request fails, Claude Code keeps the server's previously discovered tools" (v2.1.214+); on v2 the notification stream is held open with reopen limits (3 quick reopens; 5/hour then a ~6 h wait) ([dynamic tool updates](https://code.claude.com/docs/en/mcp#dynamic-tool-updates)). v2.1.271 fixed "sustained high CPU usage and repeated tool-list requests when an MCP server sends `list_changed` notifications in a tight loop".
- **Tool search / deferral.** "Tool search keeps MCP context usage low by deferring tool definitions until Claude needs them. Only tool names and server instructions load at session start … Claude Code doesn't impose a fixed per-server tool cap; the practical limit is your context window budget." `ENABLE_TOOL_SEARCH`: unset/`true` ⇒ all MCP tools deferred; `auto` ⇒ deferred once definitions reach 10 % of the context window (`auto:N` custom); `false` ⇒ all upfront. `alwaysLoad: true` per server or `_meta["anthropic/alwaysLoad"]` per tool exempts from deferral. "Claude Code truncates tool descriptions and server instructions at 2KB each" ([scale with tool search](https://code.claude.com/docs/en/mcp#scale-with-mcp-tool-search)). History: auto mode at 10 % became default in v2.1.7; full deferral is the current default.
- **Naming.** `mcp__<server-name>__<tool-name>`, with characters outside `A-Za-z0-9_-` replaced by `_` ([plugin MCP naming](https://code.claude.com/docs/en/mcp#plugin-provided-mcp-servers)). Changelog v2.1.271: "Fixed tool search returning no match when Claude selects an MCP tool by its bare name instead of its full `mcp__server__tool` name" — evidence the model does sometimes call by the wrong name.
- **Timeouts.** `MCP_TIMEOUT` (startup), per-server `timeout` / `MCP_TOOL_TIMEOUT` (default ≈ 28 h wall clock), per-request first-byte timer = max(60 s, tool timeout, `MCP_TIMEOUT`), idle timeout 5 min for HTTP and claude.ai connector servers (`CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT`); long calls are backgrounded automatically ([automatic reconnection](https://code.claude.com/docs/en/mcp#automatic-reconnection)).

### 3.4 Cowork

Tools are the claude.ai connector set "synced at session start" ([Cowork overview](https://claude.com/docs/cowork/overview)). [#811](https://github.com/anthropics/claude-ai-mcp/issues/811) (open) reports three different tool lists for one connector across web and two Cowork machines, and within one Cowork session tool schemas refreshed mid-session while `instructions` stayed at the session-start version. [#964](https://github.com/anthropics/claude-ai-mcp/issues/964) reports a built-in connector silently dropping 31 of 41 tools when a new Cowork session starts. Treat Cowork's tool catalogue as "whatever claude.ai's projection held at session start".

### 3.5 Practical limits on tool count and schema size

No client documents a hard cap. Anthropic's API guidance: "A typical multiserver setup … can consume ~55k tokens in definitions"; "Claude's ability to pick the right tool degrades once you exceed 30–50 available tools"; use tool search when "You have 10 or more tools" or "Your tool definitions consume more than 10k tokens" ([Tool search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)). Directory review: tool names ≤ 64 characters, every tool needs `title` plus `readOnlyHint`/`destructiveHint`, "Keep responses reasonably sized" ([review criteria](https://claude.com/docs/connectors/building/review-criteria)). Claude Code: 2 KB per description.

## 4. Elicitation and the out-of-band URL

### 4.1 Spec

- 2025-06-18 introduced form-mode elicitation (flat primitive schemas; "Servers **MUST NOT** use elicitation to request sensitive information") ([2025-06-18 elicitation](https://modelcontextprotocol.io/specification/2025-06-18/client/elicitation)).
- 2025-11-25 added **URL mode**: "Servers can direct users to external URLs for sensitive interactions that must *not* pass through the MCP client"; clients "MUST show the full URL to the user for examination before consent" and "MUST NOT open the URL without explicit consent"; servers "MUST NOT provide a URL which is pre-authenticated" and "MUST verify the identity of the user who opens the URL" (phishing section). URL mode "is *not* for authorizing the MCP client's access to the MCP server". Capability declared as `elicitation: { form: {}, url: {} }`; bare `elicitation: {}` means form only; "Servers **MUST NOT** send elicitation requests with modes that are not supported by the client" ([2026-07-28 elicitation](https://modelcontextprotocol.io/specification/2026-07-28/client/elicitation)).
- 2026-07-28 moved elicitation into MRTR: the server returns `resultType: "input_required"` with `inputRequests` and an opaque `requestState`; the client retries the original call with `inputResponses`; `notifications/elicitation/complete` and `elicitationId` were removed. "Servers **MUST NOT** send an `inputRequests` that the client has not declared support for" ([MRTR](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/mrtr)).
- `laravel/mcp` 0.9.5 has no server-side elicitation support (no match for `elicit` in `src/`).

### 4.2 Client support

- **Claude Code**: "Servers can request input in two ways: Form mode … URL mode: Claude Code opens a browser URL for authentication or approval. Complete the flow in the browser, then confirm in the CLI." URL length cap ≈ 8 000 chars (≈ 4 000 if percent-heavy). `Elicitation` / `ElicitationResult` hooks can auto-answer ([respond to elicitation](https://code.claude.com/docs/en/mcp#respond-to-mcp-elicitation-requests)). Added in v2.1.76; print/SDK-mode auto-cancel fixed in v2.1.117 ([changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)).
- **claude.ai**: no documentation of support. Observed `clientCapabilities` on a custom connector, 2026-08-12: `{"extensions":{"io.modelcontextprotocol/ui":{…}}}` — "There is no `elicitation` key" ([#153](https://github.com/anthropics/claude-ai-mcp/issues/153), open enhancement filed 2026-04-06, 12 comments, no Anthropic response).
- **Cowork**: declares `"elicitation": {}` on 2026-07-28, "receives and parses" the `InputRequiredResult`, logs `Elicitation request received in print mode`, and "does nothing … until the transport timeout fires at 180 seconds" ([#1046](https://github.com/anthropics/claude-ai-mcp/issues/1046), filed 2026-09-16, open).

Conclusion for brief open item 4: elicitation is usable only from Claude Code. A gateway that sends an elicitation to claude.ai violates the spec (capability not declared); sending one to Cowork hangs the call. Servers must branch on the declared capability, which laravel/mcp does not expose today.

### 4.3 Does a URL in a structured tool error reach the user?

- **claude.ai, documented**: "A `200` with `isError: true` is an application-level tool failure. Claude passes the error text to the model as the tool result and moves on — there is no auth prompt … If users are seeing 'please sign in' text in the chat instead of a **Connect** button, the server is returning the wrong one" ([lazy authentication](https://claude.com/docs/connectors/building/lazy-authentication#return-401-not-a-tool-error)). So the URL reaches the *model*; whether it reaches the *user* depends on the model relaying it. The same page shows that it commonly does ("users are seeing 'please sign in' text in the chat"), but nothing guarantees verbatim relay.
- **Claude Code**: results are given to the model; the docs do not describe user-visible rendering of MCP tool results beyond the size-spill behaviour. Unknown whether a collapsed result is expanded by the user.
- **Spec**: `isError: true` is for "API failures, invalid input data, business logic errors" ([tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools#error-handling)). Anthropic's tool-writing guidance: "prompt-engineer your error responses to clearly communicate specific and actionable improvements" ([Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)).

### 4.4 The documented client-driven browser round-trip: step-up authorization

The one mechanism every client documents for "pause the call, send the user to a browser, retry" is the OAuth step-up:

- Spec: on insufficient scope the server **SHOULD** respond `403` with `WWW-Authenticate: Bearer error="insufficient_scope", scope="…", resource_metadata="…"`; clients acting for a user **SHOULD** re-authorize with the increased scope set and retry ([2025-11-25 step-up](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization#step-up-authorization-flow)).
- claude.ai: "A `403` triggers re-authentication only when accompanied by `WWW-Authenticate: Bearer error="insufficient_scope"` for scope step-up; any other `403` is surfaced as a terminal error." "Claude prompts the user to re-authorize and, on consent, retries the same tool call with the new token." Claude unions the `403` scope with the discovery-time scope; the challenge is cached per user per server for 15 minutes; include existing scopes in the `403` or the user may lose them ([lazy authentication → step-up](https://claude.com/docs/connectors/building/lazy-authentication#step-up-authorization)). The initial `401` surfaces as "an inline **Connect** card in the conversation. The user authenticates in a popup, Claude retries the same tool call automatically".
- Claude Code: "If the server later returns a 403 `insufficient_scope` for a tool call, the call fails with a `needs additional permissions` message that names the scope the server asks for. The server shows as needing authentication in `/mcp`." Re-auth is manual (`/mcp` → Re-authenticate), and pinned `oauth.scopes` must include the new scope ([restrict scopes](https://code.claude.com/docs/en/mcp#restrict-oauth-scopes)).

This gives the elevation ticket a documented alternative to the out-of-band URL: gate dangerous tools behind an `elevated`-type scope, return `403 insufficient_scope` when the token lacks it, and have the gateway's own authorization endpoint demand TOTP/passkey before issuing a token carrying that scope. Caveats to weigh there, not here: the window becomes the token's lifetime (the AS must drop the scope on refresh or issue short-lived tokens for it); Claude Code needs a manual re-auth; laravel/mcp 0.9.5 has one fixed scope (`mcp:use`) and its `401` middleware has no `scope=`; the `403` must be produced at the HTTP layer, before the JSON-RPC handler, exactly as the `401` is.

### 4.5 Other per-call rails

- claude.ai: `destructiveHint: true` ⇒ "destructive tools always prompt"; `readOnlyHint: true` ⇒ "can run without per-call confirmation" ([review criteria](https://claude.com/docs/connectors/building/review-criteria#provide-tool-annotations)); users see "Always allow" and org owners can set `ask`/`blocked`.
- Claude Code: `_meta["anthropic/requiresUserInteraction"]: true` "shows that tool's permission prompt on every call, even in `acceptEdits`, `auto`, and `bypassPermissions` … and doesn't offer a 'don't ask again' option" (v2.1.199+); in non-interactive mode the call is denied ([require approval](https://code.claude.com/docs/en/mcp#require-approval-for-a-specific-tool)).
- Spec: "there **SHOULD** always be a human in the loop with the ability to deny tool invocations"; "clients **MUST** consider tool annotations to be untrusted" ([tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)). Neither hint is a security boundary, matching the brief's "accidents only" stance.

## 5. Result limits

- **Claude Code** (documented, [output limits](https://code.claude.com/docs/en/mcp#mcp-output-limits-and-warnings)): warning above 10 000 tokens; default max 25 000 tokens via `MAX_MCP_OUTPUT_TOKENS`; over the limit "Claude Code saves it to a file and replaces it in the conversation with a message that names the file path, so Claude reads the file when it needs the content"; a tool may set `_meta["anthropic/maxResultSizeChars"]` (text only) up to 500 000 characters. So truncation on Claude Code shows as a file reference, not a cut string.
- **claude.ai / Cowork**: Unknown. No limit is documented for connector tool results; the review checklist says "Keep responses reasonably sized for the task. Do not return a full database dump when a summary was requested" ([review criteria](https://claude.com/docs/connectors/building/review-criteria#functional-quality)). Observed on host-side tool-search payloads: "Output abbreviated due to length limit" after ~30 appended definitions ([#949](https://github.com/anthropics/claude-ai-mcp/issues/949)). Anthropic's own guidance uses Claude Code's 25 000 tokens as the reference figure and recommends "pagination, range selection, filtering, and/or truncation with sensible default parameter values" ([Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)).
- `laravel/mcp`'s `ToolSearch` caps `execute_tools` output at `mcp.tool_search.max_output_bytes` (default 65 536) and `max_tool_calls` (default 10) — a server-side precedent for capping proxied results (`config/mcp.php`, `src/Server/Tools/ToolSearch.php`).

## 6. "Fetch the schema, then call": precedent and instruction text

Three precedents, all documented:

1. **API Tool Search Tool.** Tools marked `defer_loading: true` are excluded from context; "When Claude needs additional tools, it searches using a tool search tool … The API automatically expands these references into full tool definitions … Claude selects from the discovered tools and calls them." Recommendations: "Keep your 3–5 most frequently used tools non-deferred", "Use consistent namespacing in tool names", "Add a system prompt section describing available tool categories", "Use keywords in descriptions that match how users describe tasks" ([Tool search tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-search-tool)).
2. **Claude Code `ToolSearch`.** All MCP tools deferred by default; "Server instructions help Claude understand when to search for your tools … explain: What category of tasks your tools handle; When Claude should search for your tools; Key capabilities your server provides" ([for MCP server authors](https://code.claude.com/docs/en/mcp#for-mcp-server-authors)).
3. **laravel/mcp `ToolSearch`.** `search_tools` description: "Search the tools available through execute_tools. Returns exact tool names, descriptions, and complete input schemas. An empty query browses the catalog." `execute_tools` description: "Execute one or more independent catalog tools synchronously in order. Pass {"calls":[…]} using exact names and arguments returned by search_tools. Execution stops on the first error. If a call depends on a previous result, invoke execute_tools again with a new calls array." (`src/Server/Tools/SearchTools.php`, `ExecuteTools.php`.)

What makes precedents 1 and 2 reliable is structural: the deferred tool **cannot be called until its reference is loaded**, so the model has no shortcut. Precedent 3 — and the gateway's `list-site-tools` / `call-site-tool` — has no such guarantee: `execute_tools` is always callable and relies on (a) its description naming the prerequisite ("exact names and arguments returned by search_tools") and (b) validating arguments against the catalogue schema and returning an actionable error. Evidence that models do skip or misname (Claude Code changelog v2.1.271: "Claude selects an MCP tool by its bare name instead of its full `mcp__server__tool` name") argues for (b) as the load-bearing part: an unknown-tool or invalid-argument error from `call-site-tool` should return the site tool's `inputSchema` (or say "call `list-site-tools` for `<site>` first") so the next attempt succeeds without a second round of guessing.

Where to put the instruction text: in the **tool descriptions**, not server `instructions` — claude.ai does not pass `instructions` to the model (Observed, [#93](https://github.com/anthropics/claude-ai-mcp/issues/93)) and Cowork's copy goes stale (Observed, [#811](https://github.com/anthropics/claude-ai-mcp/issues/811)); Claude Code truncates both at 2 KB ([tool search](https://code.claude.com/docs/en/mcp#for-mcp-server-authors)). Anthropic's description guidance: "Think of how you would describe your tool to a new hire … make it explicit"; "Input parameters should be unambiguously named: instead of a parameter named `user`, try a parameter named `user_id`" ([Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)); "Describe what the tool does. Do not tell Claude how to behave" (descriptions that "interfere with Claude calling other tools" are rejected from the directory — [review criteria](https://claude.com/docs/connectors/building/review-criteria#avoid-prompt-injection-patterns); this applies to directory review, not custom connectors, but is a useful bound on tone).

## 7. Quirks: `site` arguments and duplicate tool names

- **Slug vs URL.** No client documents any handling of argument formats; the model sees only the JSON Schema and description. Anthropic's guidance favours human-readable identifiers ("Agents … grapple with natural language names, terms, or identifiers significantly more successfully than they do with cryptic identifiers") and unambiguous parameter names ([Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents)). A slug that is the site's hostname (`example.com`) reads naturally in both directions; naming the parameter `site` alone invites URLs and display names — name it for what it accepts (`site_slug`, or accept both and normalise server-side, returning the canonical slug in every `list-sites` row).
- **Multiple connectors sharing tool names.** Claude Code namespaces every tool as `mcp__<server>__<tool>` and surfaces claude.ai connectors as servers named `claude.ai <name>` ([Claude Code docs](https://code.claude.com/docs/en/mcp#use-mcp-servers-from-claude-ai)); observed in this session on 2026-09-21: two claude.ai connectors (`claude.ai example.com`, `claude.ai example.net`) both expose `restlesswp-create-post` and appear as `mcp__claude_ai_example_com__restlesswp-create-post` and `mcp__claude_ai_example_net__restlesswp-create-post` with no collision. claude.ai's per-connector tool toggles and org `ask`/`blocked` controls are also per connector. A user who adds the gateway twice (e.g. staging and production URLs) therefore gets two namespaces; the risk is the model picking the wrong one, which the connector *name* (user-chosen) mitigates, not the tool name. Note the claude.ai catalogue cache is keyed by URL string ([#1044](https://github.com/anthropics/claude-ai-mcp/issues/1044)), so a second connector to the same URL shares the stale projection.
- **Non-ASCII connector names.** [#586](https://github.com/anthropics/claude-ai-mcp/issues/586) reports a Cyrillic connector display name listing tools but never calling them. Keep the suggested connector name ASCII.

## 8. Facts other tickets should carry

- **Deployment / origin guard.** Anthropic egress `160.79.104.0/21`; IPv4-only; no private DNS answers; the MCP URL must not redirect across hosts; OAuth endpoints must answer within 10 s (30 s for refresh).
- **`oauth` module.** Claude expects `invalid_grant` on dead refresh tokens, refresh-token rotation for public clients, form-urlencoded `/token`, JSON `/register`; DCR creates one Passport client per connect (claude.ai) or per login (Claude Code); CIMD needs `client_id_metadata_document_supported` + `token_endpoint_auth_methods_supported: ["none"]` and an AS that dereferences URL client IDs — neither laravel/mcp 0.9.5 nor Passport does this; the 2026-07-28 spec deprecates DCR in favour of CIMD.
- **Elevation.** The out-of-band URL is relayed by the model, not the client; `403 insufficient_scope` is the documented client-driven browser round-trip on claude.ai (automatic retry) and Claude Code (manual re-auth); elicitation is Claude Code-only today.
- **Gateway tool surface.** claude.ai's catalogue cache makes the constant surface not just convenient but necessary — any tool added to the gateway may take hours to appear on claude.ai regardless of `listChanged`. Keep descriptions under 2 KB; avoid MCP-Apps `_meta` on gateway tools; name the site parameter for what it accepts; make `call-site-tool` errors carry the schema.
